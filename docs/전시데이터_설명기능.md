# 1. 전시 데이터 & 설명 기능

`작품 정리_정리본.xlsx`(37점)를 화면과 AI가 함께 쓰는 `public/data/exhibits.json`으로 만들고,
관람객 수준에 맞춘 **쉬운 설명 / 자세한 설명**을 만들어 넣었습니다.

## 실행

```bash
node scripts/build-data.js
```

엑셀을 고친 뒤 다시 실행하면 `public/data/exhibits.json`이 새로 만들어집니다. (설치할 패키지 없음)

## 추가·변경한 파일

| 파일 | 내용 |
|---|---|
| `scripts/build-data.js` | 엑셀 → `public/data/exhibits.json` 변환 + 설명 만들기 |
| `public/data/exhibits.json` | 작품 37점 데이터 (비어 있던 파일을 채움) |
| `작품 정리_정리본.xlsx` | 원본 엑셀 (2번 담당 PR과 같은 파일) |
| `data/exhibit-ids.json` | 작품 고유 영문 ID 표 (2번 담당 PR과 같은 파일) |

화면(`public/*.html`, `public/js/*`, `css`)과 AI(`api/*`) 파일은 건드리지 않았습니다.

## 데이터 형식

한 작품에 **화면용 필드**와 **AI용 필드**가 같이 들어 있습니다.

```jsonc
{
  // 화면(3번)용 ─ README '전시물 데이터 형식'과 같은 이름
  "id": "506",                      // 작품 번호 = 챕터 번호 + 순서. 번호 찾기·지도 핀
  "name": "활옷(闊衣)",
  "hall": "5부 혼례와 가족",         // 앞의 숫자(5)로 지도 칸이 자동으로 나뉨
  "era": "약 100년 전(20세기 초)",
  "descriptionEasy": "신부가 혼례 때 입던 화려한 예복입니다. ...\n\n물결·바위·...",
  "descriptionDetail": "소개\n\n역사·문화적 배경\n\n의미\n\n추가 이야기",
  "questions": ["활옷의 무늬에는 어떤 뜻이 있나요?", "활옷과 원삼은 어떻게 다른가요?"],
  "info": [{ "label": "시대", "value": "약 100년 전(20세기 초)" }, ...],

  // AI(2번)용 ─ 2번 담당 scripts/build-exhibits.js 와 같은 필드, 엑셀 원문 그대로
  "slug": "hwalot",                 // 작품 고유 영문 ID
  "number": "506",
  "exhibition": "상설전시관 3 《한국인의 일생》",
  "chapterNo": 5,
  "title": "활옷(闊衣)", "artist": "...", "chapter": "5부 혼례와 가족",
  "basicDescription": "...", "workInfo": "...", "historicalContext": "...",
  "exhibitionMeaning": "...", "additionalInfo": "...", "expectedQuestions": "...",
  "sources": "...", "sourceUrls": [...], "sourceStatus": "일부 확인 필요", "needsReview": true, "sourceRow": 21
}
```

### 설명을 만드는 방법

- **쉬운 설명**: 기본 설명 앞 2문장 + 작품의 의미 1문장. 한자 표기 `(闊衣)`는 뺍니다.
  '파트', '챕터'처럼 전시 기획에서 쓰는 말이 든 문장은 넣지 않습니다.
- **자세한 설명**: 기본 설명 → 역사·문화적 배경 → 작품의 의미 → 추가 정보 순서로, 빈 줄로 문단을 나눕니다.
- 엑셀의 `~함/~임` 문장은 `~합니다/~입니다`로 바꿨습니다. (화면 문구, 소리로 듣기용)
- `확인 필요`, `보도자료`, `팀원 확인` 같은 조사 메모 문장은 관람객 설명에서 뺐습니다.
  AI용 원문 필드에는 그대로 남아 있어서, AI는 확인되지 않은 내용을 구분할 수 있습니다.

## 다른 담당과의 연결 확인 결과

**3번 화면 ✅** 지도에 1~9부가 자동으로 나뉘고, 번호 찾기·설명 탭·추천·이전/다음이 모두 동작합니다.
`hall`에 챕터 이름을 넣어서 `home.js`의 `HALL_NAMES`는 비워 둬도 됩니다.

**2번 AI ✅** `api/docent.js`가 `exhibitId: "506"`으로 작품을 찾고, 원문 필드로 AI 지시문을 만듭니다.
(`hall`이 '상설전시관 3' 대신 '5부 혼례와 가족'이 되어서, 지시문의 `전시관:` 줄에 챕터가 나옵니다.
전시관 이름이 필요하면 `exhibition` 필드를 쓰면 됩니다.)

**2번 ↔ 3번 요청 형식 ❌ (맞춰야 함)**
화면은 `{ name, id, question }`을 보내는데, AI 서버는 `{ exhibitId, level, question }`을 받아서
지금은 `400 어떤 전시물에 대한 질문인지 알 수 없습니다`가 납니다. 둘 중 하나만 고치면 됩니다.

- 화면 쪽 (`public/js/exhibit.js` 맨 위 연결 설정):
  ```js
  function buildRequest(ex, question) {
    return { exhibitId: ex.id, level: mode, question, name: ex.name, id: ex.id };
  }
  ```
- 또는 AI 쪽 (`api/docent.js`):
  ```js
  const requestedId = String(body.exhibitId ?? body.id ?? "").trim();
  ```

**2번 PR과 겹치는 부분**
- 2번 PR의 `scripts/build-exhibits.js`도 같은 엑셀로 `exhibits.json`을 만듭니다.
  `build-data.js`는 그 필드를 모두 그대로 만들고 화면용 필드를 더한 것이라, PR을 합칠 때
  `exhibits.json`이 충돌하면 `node scripts/build-data.js`를 다시 실행해서 해결하면 됩니다.
  이후에는 둘 중 하나만 쓰기로 정하는 것을 권합니다.
- 2번 PR은 `public/index.html`, `exhibit.html`, `js/exhibit.js`, `css/style.css`도 바꿔서
  3번이 master에 올린 화면과 충돌합니다. 합칠 때 화면 파일은 3번 것을 쓰는지 정해야 합니다.
